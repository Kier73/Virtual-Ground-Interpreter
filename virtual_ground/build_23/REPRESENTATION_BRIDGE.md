# Virtual Ground and the Relational Representation Atlas

Build 23 concerns the generative logic that produces possible states and transformations. The harmonic and path representations developed in earlier builds are different objects: they provide observer-adapted coordinates for the system, its trajectories or its temporal observations.

A useful layered view is:

\[
\mathfrak G
\xrightarrow{\text{generate}} (S,T)
\xrightarrow{O} \mathcal D_O
\xrightarrow{\rho_O} H_O
\xrightarrow{K_O} \text{relational geometry}
\]

- `G`: Virtual Ground, the generative operational rules.
- `(S,T)`: states and transitions generated by those rules.
- `O`: observer mapping and measurement limitations.
- `D_O`: observed traces, event streams or state samples.
- `rho_O`: selected representation (harmonic, path-signature, graph, symbolic, quotient, etc.).
- `K_O`: a kernel or relational geometry derived from the representation.

## Distinct roles

### Ground

The ground defines which states and operations are possible and how they compose. In Build 23 it is a bounded symbolic rule program inferred from transition data.

### Path signature

A path signature describes ordered history in a representation space. It can encode distinctions between trajectories with equal endpoints. It is not itself the state-transition law.

### Harmonic representation

A harmonic decomposition makes a selected symmetry action intelligible. It can expose invariant sectors, phase, frequency or rotational representation content. The choice depends on the symmetry group acting on the ground's trajectories or observables.

### Event graph

An event graph describes observed events, local order, recurrence and inferred correspondence. It is useful when clocks or observations are partial. It does not automatically reveal unobserved transition rules.

### Observer kernel

A kernel compares represented observations. It produces relational geometry but cannot recover distinctions omitted by the observer map or representation.

## The central composition

A future Virtual Layer-native interpreter should not choose a representation by fashion or by a fixed transform order. It should:

1. infer or receive a candidate ground;
2. identify the transformation algebra relevant to the task;
3. determine which distinctions the observer can measure;
4. choose a representation whose equivariance/invariance properties match those transformations;
5. audit whether the representation is sufficient for the intended task;
6. synthesize navigation in that representation;
7. verify the resulting state transition under the ground.

This supports the user's distinction between conventional operation sequences and navigation from a higher-level description. A higher-level route may shorten planning or select a macro, but it does not reduce physical work unless the target system exposes an efficient macro operation or the representation permits a genuinely cheaper computation.

## Candidate future test

Given an induced ground, generate two families of trajectories that reach the same endpoint. Compare endpoint harmonics, path signatures, event graphs and observer kernels. Then change the ground's transition law while keeping the state encoding fixed. Determine which representation changes, which invariants remain, and whether a task policy can transfer without full retraining.

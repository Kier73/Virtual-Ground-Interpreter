# Next Investigation — Build 30

Build 29 creates event candidates using fixed feature families and several boundary thresholds. Next investigate whether the interpreter can learn the observer representation itself.

1. Adaptive frame scale and hop selection from signal stability and task requirements.
2. Calibrate and compare channel-specific transfer functions before fusion.
3. Improve phase-only and transient event discovery with an analytic-signal / instantaneous-phase branch and explicit uncertainty.
4. Learn feature weights and token similarity thresholds from held-out predictive usefulness, not boundary truth.
5. Maintain competing event vocabularies and segmentations as observer-specific quotients.
6. Ask which event representation best predicts future observations and operation effects.
7. Preserve the distinction between predictive utility, semantic interpretation and causality.

The target is not a universal event tokenizer. It is a Virtual Ground observer that can select and revise its measurement representation according to intention, available resources and independently verified predictive performance.

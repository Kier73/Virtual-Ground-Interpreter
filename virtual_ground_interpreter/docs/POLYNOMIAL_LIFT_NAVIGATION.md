# GEOMETRY-FIRST-002 — Discovery of polynomially lifted navigation

**Status:** executable, finite, synthetic-Ground research experiment. The certificates are exact within one enumerated transition snapshot, not authority to infer unseen external behavior.

## Question

Can a geometry whose coordinate transitions are nonlinear reveal **additional coordinates** in which those transitions are affine, allowing the existing VGI algebraic power to navigate distant logical timestamps without traversing all intermediate states?

The first experiment, `GEOMETRY_FIRST_COMPUTATION.md`, found affine transformations on a finite torus but conservatively refused the nonlinear `epsilon` transformation. Here we extend the *discovery* stage, not the trusted algebraic powering implementation.

## Separate the three things

1. **Observed Ground:** a complete finite transition snapshot with point positions, a single opaque action identity, and one successor edge per source state. A SHA-256 fingerprint binds precisely those entries. A synthetic snapshot is not independently authenticated evidence about a physical system.
2. **Representation discovery:** choose a finite-field chart, a bounded polynomial search degree, and candidate monomials; fit successor polynomials from rank-independent probe points; check **every** source/target edge before accepting a relation; repeatedly add features needed to close the selected feature set under the action.
3. **Navigation:** the result is an affine transformation on the expanded feature vector. Use VGI's existing `ModularAffineMap.power()` over the finite field to reach a requested nonnegative logical coordinate. Project to the original chart and verify the lifted feature invariant on the returned state.

The three elements are independently fingerprinted or represented. Seeded SHA-256 point identities are orthogonal to the structural law: they cannot themselves reveal a result or supply a semantic distance. No precomputed table for distant iterations is stored.

## Actual discovered result

On the 10,201-point torus `F_101²`, the opaque action `epsilon` has the declared transition table generated by

\[
(x,y)\to(x+y^2,y+1)\quad \text{over }\mathbb F_{101}.
\]

The discovery algorithm is **not told** that the third coordinate should be `y²`. It uses six independent fitting probes to infer degree-two successor polynomials for `x` and `y`. Closure of their dependencies adds `z=y²`, and fitting the successor of `z` gives

\[
\begin{aligned}
x' &= x+z\\
y' &= y+1\\
z' &= z+2y+1.
\end{aligned}
\]

Equivalently,

\[
\begin{bmatrix}x'\\y'\\z'\end{bmatrix}
=\underbrace{\begin{bmatrix}1&0&1\\0&1&0\\0&2&1\end{bmatrix}}_M
\begin{bmatrix}x\\y\\z\end{bmatrix}
+\begin{bmatrix}0\\1\\1\end{bmatrix}\pmod{101}.
\]

The certificate checks the above map on **all 10,201 declared transitions**, not only the six fitted probe points. By induction it therefore agrees with every reachable future state of this finite deterministic Ground, for every start state and all nonnegative logical times. Runtime queries use `ModularAffineMap` homogeneous matrix exponentiation, `O(log t)` in the number of matrix compositions for fixed dimension, rather than iterating the state transition `t` times. Dense matrix multiplication still carries dimension and bit-operation costs; the certificate construction costs `O(|S|)` complete edge audits plus fitting/search work.

The immutable snapshot and certificate SHA-256 fingerprints are computed once at admission, not rehashed over all 10,201 edges for every query. This preserves the intended logarithmic logical-time query complexity. The invariant `z = y² mod 101` is independently checked on returned coordinates. The verified coordinate at **`t = 10^30 + 11`** from `(39,47)` is **`(81,57)`**; the lifted coordinate `z=17`. An independent integer sum-of-squares formula checks the large-t result.

### A richer second case

A separate cubic Ground, `x' = x + y³, y' = y+1`, **fails** the degree-two search. Raising the declared degree budget to three makes the algorithm discover two auxiliary features, `y²` and `y³`. Their transitions close into an affine **four-dimensional** map. This is the meaningful distinction: discovery of an appropriate representation, not the manually supplied answer to an algorithm. It remains a bounded polynomial method, not a general nonlinear dynamical systems solver.

## Controls

- **Independent repeated stepping:** compare every returned finite-time state against direct indexing of the observed transition snapshot across randomized starts, primes 5/7/11/17, and multiple horizons.
- **Independent distant-time formula:** compare `10^40+71` time navigation with the exact integer sum of squares (do not use the discovered transform to construct the expected answer).
- **Degree and domain refusals:** degree one cannot fit the nonlinear `epsilon` map; degree two cannot fit the cubic map over `F_7`; composite moduli, nonprime/oversized charts, oversized degrees and malformed target tables are refused.
- **Tampered evidence:** editing exactly one source edge invalidates the candidate, unless it happens to define another fully valid low-degree observed map; the fingerprint changes for any edit.
- **Certificate integrity:** a constructed certificate is independently checked against every snapshot edge and validates its fitting probes; merely asserting a certificate is insufficient.
- **Dynamic initial state:** navigation receives the start state and logical timestamp at query time. It does not require enumerating every possible long-time answer in advance.

## Local Python baseline (2026-11-14)

The following measurements were produced in an **isolated API-compatible harness** because the full VGI checkout was not mounted; only GitHub CI can assert the actual integrated package. The values are exploratory, not hardware-independent performance claims.

| Operation | Median wall time |
|---|---:|
| Degree-two discovery + full-domain certification (3 repetitions) | ~139 ms |
| Query `t=10^30+11` after certification (7 repetitions) | ~0.89 ms |
| Direct 250,000 transitions from an existing table (3 repetitions) | ~5.01 ms |
| Query `t=250,000` using affine power (7 repetitions) | ~0.16 ms |

A fair amortized comparison **includes** the ~139 ms preprocessing plus the original cost of building/admitting the full 10,201-edge Ground. For a few small queries, conventional execution wins; for many long-time requests to the same certified map, the preprocessing may amortize. The iterative baseline uses **fast table lookups**, rather than the underlying function, to avoid biasing it against navigation. This experiment tests a finite mathematical law, not an arbitrary runtime matrix multiplication accelerator.

## E-CPU correspondence — proposed, not yet wired

The current E-CPU repository already has an authenticated computational-host and hypervisor stack, `navigation_admission.py`, `navigation_bridge.py`, `navigable_computation_checkpoint.py`, and `transit_vgi.py`. These should be reused rather than establishing an ungoverned execution channel.

A future pure operator such as `geometry.polynomial_lift.navigate` can take a **request** `(snapshot_fingerprint, certificate_fingerprint, action, initial_coordinates, logical_tick)` and return a **receipt** `(computed_coordinates, lifted_coordinates, certificate_fingerprint, execution_method, implementation_fingerprint, resource_costs)`. The receiving host must re-admit the exact Ground and verify the mathematical certificate (or authenticate an independently checked certificate with its trusted provenance) before accepting any result. A digest alone does not prove the certificate; an algebraic navigation claim is not a hypervisor grant. Rehoming and replay safety remain the responsibility of E-CPU's existing fabric governance, not this exploratory module.

Potential research next: **on-demand partial observations and active-attention-guided choice of missing edge probes**. Full enumeration here is an intentionally conservative proof control, not a general solution for large or open-ended state spaces. Additional targets include piecewise polynomial actions, cross-observer chart changes, and recognizing algebraic generators from independent state observations.
